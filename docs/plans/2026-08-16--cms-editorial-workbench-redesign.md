# 少惰主 CMS 内容工作台与文章编辑器改版设计

- 状态：已由用户逐节确认
- 设计日期：2026-08-16
- 适用系统：`sdzjoy.com` 主站 Wagtail CMS
- 当前版本：Django 5.2 / Wagtail 7.4
- 本文范围：CMS 首页、内容列表、文章编辑器、专业内容块、保存发布、容错与验收
- 非本文范围：多人投稿审核、评论社区、AI 自动写作、整篇 DOCX/Markdown 导入、规范库自动抓取

## 1. 背景与目标

现有 CMS 已具备文章、随记、项目和工具的基础数据模型，也为各类页面注册了独立列表入口，但后台仍接近原生 Wagtail：工作台缺少写作导向，文章字段在一个长表单中平铺，正文块没有专业分组，主题色之外几乎没有针对中文技术写作的界面设计。

本次改版的目标不是把后台换一套皮肤，而是把日常任务缩短为一条明确路径：

```text
进入内容工作台
  ↓
新建文章或继续草稿
  ↓
沉浸式编辑正文
  ↓
补充项目、主题、封面和搜索信息
  ↓
预览
  ↓
站长直接发布
```

成功标准：站长进入 CMS 后无需经过页面树即可开始写作；长文章的正文区域稳定、清晰；工程公式、规范引用、表格和图片具备结构化输入；旧文章无需人工迁移；保存失败、错误公式和异常内容块不会造成正文丢失或整页崩溃。

## 2. 方案选择与开源借鉴

采用“保留现有 Wagtail 与数据模型，自研轻量技术写作工作台”的路线。

借鉴范围：

- Wagtail Bakery Demo：博客内容模型、可复用内容块、图片库和后台钩子；
- CodeRed CMS / Wagtail CRX：内容块分类、结构化组件、文章与 SEO 信息组织；
- Puput：文章分类、归档、关联内容和博客列表信息密度；
- Wagtail 7.4 官方接口：`TabbedInterface`、面板系统、后台首页组件、`PageListingViewSet`、StreamField 和 Draftail。

不直接安装 CodeRed CMS 或 Puput。两者会引入与现有文章、项目、主题、搜索和权限重复的数据模型，以及大量当前不需要的营销建站组件。新增能力优先使用 Wagtail 7.4 原生接口，避免后台升级时被废弃扩展锁定。

## 3. 编辑与发布边界

- 编辑方式：可视化块编辑器；
- 页面布局：沉浸式单栏正文，辅助资料位于可收起侧栏或次级面板；
- 内容来源：直接在后台写作，同时兼容从 Word、网页和微信复制；
- 公式：LaTeX 源码与即时预览；
- 引用：结构化规范、标准、手册、论文和网页引用；
- 发布流程：当前仅站长写作和直接发布，不启用投稿、审核和多人工作流；
- 数据边界：保留现有 `ArticlePage`、历史版本和正文 JSON，不批量重写旧内容；
- 文件边界：文章图片和小型附件进入 Wagtail 媒体库；资源站的大文件继续使用外部网盘，不混入文章媒体卷。

## 4. CMS 首页：少惰主内容工作台

后台首页替换通用欢迎区，突出写作任务而非系统对象。

首屏包含：

1. “新建文章”和“新建随记”两个主要操作；
2. 最近草稿，显示标题、最后修改时间和继续编辑入口；
3. 最近发布，显示公开状态和前台查看入口；
4. 内容概况：文章、随记、项目、工具、图片与文档数量；
5. 待整理随记：尚未关联成文文章的随记；
6. 快捷入口：主题、图片库、文件库和主站首页。

首页不展示虚假趋势、无数据图表或多人审核队列。内容面板必须使用 Wagtail 官方组件与权限判断，避免另建一套平行后台。

## 5. 内容列表

文章、随记、项目和工具继续使用独立工作台入口，菜单顺序按实际频率排列：内容工作台、文章、随记、项目、工具、图片与文件、资料管理、低频系统功能。

文章列表至少显示：

- 标题；
- 草稿、已发布或有未发布修改；
- 文章日期；
- 所属项目；
- 主题；
- 预计阅读时间；
- 首页推荐状态；
- 最后修改时间。

支持标题搜索，并按发布状态、项目、主题、日期和首页推荐筛选。点击标题直接编辑。新增文章时若只有一个合法文章父栏目，应直接进入新建表单，不要求站长先理解 Wagtail 页面树。

## 6. 沉浸式文章编辑页

页面中央为写作画布，推荐正文宽度约 760-880 像素；大屏幕保留足够留白，小屏幕使用完整单栏。

主要顺序：

1. 标题；
2. 摘要；
3. 可选封面图；
4. 正文块编辑器。

页面顶部固定精简操作栏，清楚区分：保存草稿、预览、发布。显示草稿、已发布、存在未保存修改、保存中、保存成功和保存失败等状态。支持 `Ctrl+S` 保存草稿；检测到未保存修改时，离开页面应提示。

文章日期、所属项目、主题、首页推荐、阅读时间、URL、搜索摘要和其他发布字段放入可收起的文章资料区域。系统级字段与低频设置继续留在 Wagtail 设置区域，不占据主要写作画布。

## 7. 正文内容块

正文块选择器分为四组。

### 7.1 文字内容

- 正文段落：粗体、斜体、行内代码、上下标、删除线、链接、编号列表、项目列表和引用；
- 章节标题：二级、三级和四级标题，参与文章目录；
- 分隔线：用于长文章章节分隔；
- 提示框：说明、提示、注意、警告和工程经验五种语义。

### 7.2 工程资料

- 工程公式；
- 规范与资料引用；
- 数据表格；
- 参数卡片。

### 7.3 媒体附件

- 图片与图注；
- 文件附件；
- 外部资料链接。

### 7.4 技术内容

- 代码块；
- 命令行或配置片段。

保留现有 `heading`、`paragraph`、`markdown`、`code`、`image` 和 `table` 块名及渲染能力，新增块只扩展 StreamField 定义。旧块不做不可逆转换，保证现有页面和历史版本可继续编辑。

## 8. 专业内容块定义

### 8.1 工程公式

字段：LaTeX 源码、可选公式编号、说明，以及可重复的变量、含义和单位。

后台即时预览；前台统一渲染。数学渲染资源随站点部署，不依赖公共 CDN。语法错误时保留源码并显示就地错误，不得用空白替换。移动端公式过宽时允许横向滚动。

### 8.2 规范与资料引用

字段：资料类型、标准号或编号、中文名、英文名、年份或版本、条文号、页码、引用摘要、来源机构、来源链接、查阅日期和编辑备注。

当前允许手工填写。以后规范目录库具备稳定数据后，可增加搜索标准号并带入资料的 chooser，不改变文章中已保存的引用结构。正文中显示专业引用卡片；文章末尾按标准号和版本合并生成参考资料清单。

### 8.3 图片与图注

字段：Wagtail 图片、替代文字、图注、来源或版权说明、显示宽度。上传前检查文件类型与体积；不得把外部网页中的临时图片地址静默保存为本站图片。

### 8.4 数据表格

字段：标题、表格数据、单位说明、数据来源和表下注释。编辑器适合工程数据输入；移动端外层允许横向滚动。

### 8.5 参数卡片

用于展示设计温度、功率、流量、压差、效率等关键结果。每项包含参数名、数值、单位和可选说明；视觉上是数据摘要，不替代完整计算过程。

### 8.6 代码块与附件

代码块包含语言、源码、说明和是否显示行号。文件附件包含文档、显示名称、版本和说明。大体积资源站文件不通过该块上传，而使用外部网盘资源条目。

## 9. Word、网页与微信粘贴

粘贴清理应保留标题层级、段落、粗体、斜体、列表、引用、链接和可转换表格，同时移除字体、字号、行距、颜色、空白段落、隐藏标记和无意义嵌套标签。

规则：

- 不把来源页面 CSS 带入文章；
- 不静默删除正文和链接；
- 外部图片提示重新上传；
- 可识别的代码允许转换为代码块；
- 清理完成后以非阻塞提示显示处理概况；
- 清理器发生异常时退回安全纯文本或 Wagtail 默认粘贴行为，不应阻止用户保存。

## 10. 数据流与兼容性

```text
编辑器输入
  ↓
Wagtail 表单与块级校验
  ↓
StreamField 结构化 JSON
  ↓
页面修订版本
  ├─ 预览：使用当前修订与正式模板
  └─ 发布：生成新的公开页面版本
       ↓
前台块模板渲染
       ↓
提取引用并生成参考资料清单
```

封面图可作为 `ArticlePage` 的可空外键新增。阅读时间以自动估算为默认，同时保留人工覆盖能力；具体实现不得在每次读取页面时重复进行昂贵计算。

新增块导致的 StreamField schema migration 只更新模型定义，不重写已存 JSON。迁移前后应使用旧文章样本验证序列化、编辑和渲染。

## 11. 容错与安全

- 保存、预览、发布按钮语义必须明确，避免误发布；
- 页面离开保护不得在无修改时误报；
- LaTeX 预览错误不删除源码；
- 引用链接只作为用户提供的 URL 保存，不在后台自动抓取陌生站点；
- 富文本、Markdown、表格和公式输出继续经过安全渲染或转义；
- 图片与附件使用 Wagtail 权限和文件校验；
- 单个块异常应安全降级并记录错误，不能导致整篇文章 500；
- CMS 与 Django 管理后台继续强制 MFA；
- 自定义后台入口继续遵守 Wagtail 页面权限，不能只靠隐藏菜单控制访问。

## 12. 视觉规范

后台延续主站的暖白纸张色、深色文字、青绿色强调和编辑出版感，但保持工具界面的清晰度：

- 中文正文和表单使用清晰的系统无衬线字体；
- 标题、字段说明和操作按钮建立稳定层级；
- 扩大主要输入区和点击区域；
- 减少不必要阴影、圆角和装饰；
- 高风险发布操作与普通保存具有明确差异；
- 错误、警告、成功状态不只依赖颜色；
- 兼容桌面、笔记本和手机宽度；
- 不覆盖 Wagtail 的核心可访问性与键盘行为。

## 13. 测试与验收

自动化测试至少覆盖：

1. 新内容块序列化、反序列化和前台渲染；
2. 旧正文 JSON 在新模型下继续加载；
3. 文章新建、保存草稿、预览和发布；
4. 封面图和阅读时间；
5. LaTeX 正常与错误输入；
6. 结构化引用汇总与去重；
7. 图片、表格、参数卡、代码和附件渲染；
8. 文章列表的列、搜索、排序与筛选；
9. CMS 首页只向有权限用户显示可执行操作；
10. 站长 MFA 门槛不被自定义视图绕过；
11. Word/网页粘贴清理的允许和移除规则；
12. 公共文章页、搜索、RSS 与既有内容不回归。

人工验收使用桌面和手机视口完成：新建一篇包含标题、富文本、图片、公式、规范引用、表格和代码的测试草稿；检查编辑、预览、发布、再次编辑和历史版本。测试数据在验收后清理，或明确保留为非公开示例。

## 14. 部署与回退

发布前执行代码检查、完整测试、迁移检查和生产配置检查。服务器端先备份数据库、媒体卷、环境文件和 Compose 配置，再部署不可变镜像。迁移完成且新容器健康后才切换运行版本。

验收包括 CMS 登录、MFA、内容工作台、文章列表、编辑器、预览、正式页面、后台日志、Tunnel 和原有暖通站。若迁移、健康检查或文章兼容验证失败，停止切换并恢复上一镜像；数据库只在明确需要且经过确认时使用备份恢复。

## 15. 后续而非本期

- 编辑人员投稿与站长审核；
- 多人实时协作；
- 整篇 DOCX 或 Markdown 导入；
- AI 改写、摘要或自动标签；
- 规范库搜索 chooser 与引用自动补全；
- 评论、付费内容或社区工作流。

这些能力只有在真实使用需要出现后再加入，不提前增加后台复杂度。
