# 少惰主自有 CMS 与 Wagtail 一次性替换设计

- 日期：2026-08-17
- 状态：已与站长逐段确认
- 实施分支：`feat/custom-cms-replacement`
- 目标：用简单、中文、所见即所得的自有后台完整替换 Wagtail，同时保持公开主站的视觉、栏目和网址不变

## 一、背景与产品决定

现有站点基于 Django 与 Wagtail。Wagtail 提供页面树、StreamField、修订、图片、文件和管理后台，但这些通用 CMS 概念给单人技术博客带来了过高的操作负担。站长日常需要的是快速写作、预览、发布，以及维护标准规范目录、网盘资源和会员等级；不需要页面树、集合、工作流和复杂面板。

经过比较，设计采用以下决定：

1. 不安装 Halo，不引入第二套 Java 服务、数据库、账号和权限系统。
2. 不在 Wagtail 外面继续套壳；最终镜像不再包含 Wagtail 运行依赖。
3. 在现有 Django 项目中建设“少惰主后台”，复用账号、MFA、会员等级、标准库、资源站、搜索、通知和部署体系。
4. 正文采用与 Halo 类似的 Tiptap 所见即所得编辑体验，交互接近微信公众号。
5. 一次性替换后台和内容数据层；公开主站保持当前 Anthropic 风格、栏目和网址。

Halo 的文章编辑器把写作、设置、预览、保存和发布清晰分离，其默认编辑器基于 Tiptap，并支持工具栏、悬浮菜单、斜杠命令和拖拽扩展。本项目借鉴这些交互原则，不复制 Halo 的插件与运行架构。

参考：

- <https://docs.halo.run/user-guide/posts>
- <https://docs.halo.run/developer-guide/plugin/extension-points/ui/default-editor-extension-create>

## 二、目标与非目标

### 2.1 目标

- 打开后台后最多两次点击即可开始写文章或继续草稿。
- 写作第一屏只出现标题、摘要、正文、预览、保存和发布。
- 正文像微信公众号一样直接排版，支持粘贴、图片、表格和专业暖通内容。
- 不向站长暴露页面树、模型、节点、集合、修订对象等技术词语。
- 草稿修改不影响线上版本；自动保存失败时正文不能丢失。
- 主站现有视觉、公开 URL、RSS、站点地图和搜索行为保持兼容。
- 账号、MFA、会员等级、标准库和网盘资源权限继续工作。
- 最终代码、设置、路由、模型和生产镜像不再依赖 Wagtail。

### 2.2 非目标

- 第一版不实现多人审批流。
- 第一版不实现插件市场、主题市场和可编程页面搭建器。
- 第一版不实现复杂定时发布、评论审核或多语言内容。
- 不把规范 PDF、手册或大型资源文件上传到网站服务器。
- 不同时重做公开主站视觉。

## 三、总体架构

公开页面继续由 Django 模板渲染。首页、文章、项目、随记、工具、关于、搜索、RSS 和站点地图保留现有路径与视觉，只更换查询的数据模型。

后台由新的 `studio` 应用承载：

```text
/cms/                         后台首页
/cms/content/                 内容列表
/cms/content/articles/new/    新建文章
/cms/content/articles/<id>/   编辑文章
/cms/assets/                  图片与附件
/cms/resources/               网盘资源
/cms/users/                   后台用户与会员
/cms/settings/                网站设置
/cms/api/                     自动保存、上传、预览等接口
```

`/django-admin/` 继续保留为站长应急维护入口，但不作为日常内容后台。所有 `/cms/` 页面要求账号有效、具备后台角色并已启用 MFA。

前端编辑器放在独立构建目录，通过 Tiptap 及必要扩展生成版本化静态资源。Docker 使用前端构建阶段生成资源，再复制到 Python 运行镜像；生产环境不运行 Node 服务。

## 四、内容与数据模型

Wagtail 页面模型改为普通 Django 模型：

- `Article`：文章；
- `Project`：项目；
- `Note`：随记；
- `Tool`：工具；
- `SiteProfile`：网站名称、简介、关于内容与默认素材；
- `Topic`：主题与标签；
- `Asset`：图片和普通附件；
- `ContentRevision`：人工保存、发布和恢复前的历史版本；
- `DeletedContent` 或软删除字段：回收站状态与清理时间。

发布类模型共享以下语义：

- 标题、别名和摘要；
- 草稿或已发布状态；
- 作者、创建时间、修改时间和发布时间；
- 主题、封面和推荐状态；
- 编辑中的正文与当前线上正文；
- 乐观锁版本号，用于防止多窗口相互覆盖。

正文保存为：

- `body_json`：带 `schema_version` 的 Tiptap/ProseMirror 结构，用于再次编辑；
- `rendered_html`：服务器按白名单生成并净化的 HTML，用于公开页面；
- `body_text`：抽取出的纯文本，用于搜索、摘要和阅读时间。

浏览器提交的 HTML 不直接进入公开页面。服务器验证 JSON 节点、标记与属性，再转义文本、渲染允许的节点，最后执行 HTML 白名单净化。未知节点不造成整篇文章失败：系统保留原 JSON，将该节点降级为可识别的安全占位内容，并在编辑器中提示。

## 五、写作与发布体验

文章编辑页使用全宽沉浸布局，不显示仪表盘或固定侧栏。

顶部固定栏：

```text
← 文章列表       草稿 · 已自动保存       预览  保存  发布
```

正文区域只包含标题、摘要与编辑器。摘要默认由正文生成；点击“修改摘要”后才出现手工输入。封面、分类、标签、发布日期、推荐状态和网址别名进入“文章设置”抽屉，默认收起。

常驻工具栏控制在一行：

- 正文、二级标题和三级标题；
- 加粗、斜体和删除线；
- 文字颜色和背景色；
- 有序、无序列表；
- 引用、链接和图片；
- 撤销、重做；
- 更多插入。

选中文字时只显示加粗、颜色、链接和清除格式。输入 `/` 打开可搜索的快捷菜单，插入图片、表格、提示框、公式、规范引用、参数卡、代码、分隔线和网盘资源。

图片支持选择上传、拖入和剪贴板粘贴；上传成功后才插入正文。表格支持常规增删行列。公式弹窗接受 LaTeX 并显示即时预览，保存原始 LaTeX 与安全 MathML/HTML。专业节点以 Tiptap 自定义节点实现，不把一组复杂表单直接铺在写作页面中。

自动保存采用输入停止后的延迟保存与低频保底保存。页面明确显示正在保存、已保存、离线或保存失败。断网时把尚未同步的 JSON 保存到浏览器本地；重新联网后比较服务器版本号，安全时自动同步，有冲突时生成冲突副本，绝不静默覆盖。

发布弹窗只展示标题、公开网址和可见性。发布成功后保留在编辑页，并提供“查看文章”。

## 六、后台首页、内容列表与资料库

左侧导航固定为：

```text
首页
内容
资料库
用户
设置
```

后台首页顶部只提供“写文章”主操作。页面主体显示最近草稿、最近发布和待处理事项；访问量与数量统计放在底部，不使用大面积图表。

内容页默认展示文章，并可切换项目、随记、工具和独立页面。列表仅显示标题与摘要、状态、分类标签、最后修改时间，以及编辑、预览和更多操作。搜索始终可见；状态、分类和日期筛选默认收起。行尾更多菜单承载删除、取消发布等低频操作。批量操作只保留发布、取消发布和移入回收站。

资料库分为：

1. 图片素材：文章封面和正文图片，支持上传、搜索、复制地址及查看引用位置；
2. 网盘资源：保存资源名称、平台、链接、提取信息、版本、说明和最低可见等级。

规范 PDF、手册和大型资料继续位于百度网盘、阿里云盘、115、pCloud、夸克等外部平台。服务器只保存目录元数据、封面、说明和受权限控制的链接。站内图片继续保存在媒体卷并纳入备份。

## 七、权限与会员边界

后台权限只有三个角色：

- 站长：管理全部内容、用户、等级和设置；
- 编辑：创建、编辑、预览、发布内容和管理图片；
- 资料管理员：维护标准目录与网盘资源，不接触网站设置。

会员等级继续控制前台内容或资源链接的可见范围，不与后台编辑角色混用。所有敏感判断由服务器执行；前端隐藏按钮不能代替权限校验。

后台保持现有 MFA 强制规则、CSRF、防暴力登录、私有缓存头和操作审计。修改用户等级、永久删除内容、显示受限资源链接等操作记录操作者、时间、对象和原因。

## 八、版本、回收站与错误处理

系统在手工保存、发布和恢复前创建版本；普通自动保存不产生版本洪水。每项内容默认保留最近 30 个版本。版本页面只显示时间、操作者和修改摘要，并提供预览与恢复。

删除先进入回收站，30 天后才允许彻底清理。已发布内容与编辑草稿分开保存，修改草稿不影响线上版本。恢复旧版本前先保存当前状态，因此恢复操作本身也可以撤回。

错误处理遵循以下原则：

- 网络中断保留浏览器本地副本；
- 自动保存失败显示明确提示和重试按钮；
- 版本冲突生成冲突副本，不覆盖较新内容；
- 图片上传失败不插入无效地址；
- 公式和专业节点渲染失败时保留原始数据并安全降级；
- 发布事务失败时保持原线上版本不变；
- 清理或迁移失败时停止部署，不继续删除旧数据。

## 九、安全设计

- 编辑器 JSON执行节点、标记、属性、深度和总长度限制；
- 输出 HTML仅允许业务需要的标签与属性；
- 拒绝脚本、事件属性、危险 URL、任意 iframe 和未经许可的嵌入代码；
- 图片验证真实 MIME、文件头、尺寸、像素总量与文件大小，并重新生成安全文件名；
- 上传、自动保存、预览和发布接口分别限流；
- 网盘提取信息只在通过服务器端等级检查后返回；
- 所有后台响应使用 `private, no-store`；
- 关键写操作使用数据库事务和乐观锁；
- 日志不记录正文、提取信息、密码、令牌或 MFA 密钥。

## 十、迁移与一次性切换

“一次性替换”指用户只经历一次公开切换。为保证 Django 迁移历史可控，内部发布分为两个连续阶段，并在同一维护窗口完成：

### 10.1 兼容迁移阶段

1. 备份数据库、媒体、环境文件与编排配置，并做隔离恢复演练；
2. 在仍可加载旧 Wagtail 迁移的兼容镜像中创建新内容表；
3. 复制首页配置、栏目、主题、图片和现有内容；
4. 把 StreamField 内容转换为新编辑器 JSON和服务器 HTML；
5. 对比每种内容数量、标题、别名、公开 URL和媒体引用；
6. 迁移异常时回滚事务，线上继续运行旧镜像。

### 10.2 最终切换阶段

1. 部署不含 Wagtail 运行依赖的最终镜像；
2. 切换 `/cms/`、公开内容、RSS、站点地图和搜索信号；
3. 执行完整健康、权限、编辑和公开页面验收；
4. 校验通过后清理 Wagtail 路由、设置、模板钩子和运行代码；
5. 旧表按已确认的清理迁移处理，数据库备份与旧镜像作为恢复来源；
6. 任何关键验收失败立即恢复旧镜像；若新 schema 已产生不兼容写入，再按明确方案恢复数据库。

旧迁移将通过经过验证的替换/压缩迁移处理，保证新数据库可从零安装，生产数据库也能识别既有迁移历史。不得直接删除旧迁移文件后在生产环境伪造迁移状态。

## 十一、测试与验收

### 11.1 自动测试

- 新模型、状态转换、别名唯一性与阅读时间；
- JSON验证、HTML渲染、XSS和危险链接；
- 图片上传的格式、大小、像素和权限边界；
- 自动保存、乐观锁、冲突副本和浏览器恢复数据协议；
- 草稿、发布版本、恢复和回收站；
- 三种后台角色与前台会员等级隔离；
- 文章、项目、随记、工具、关于、RSS、站点地图和搜索；
- 旧内容转换、数量核对、URL兼容和失败回滚；
- 无 Wagtail依赖的全新数据库安装测试。

### 11.2 浏览器验收

- 桌面与手机端后台首页、列表和编辑器；
- 中文输入法、Word/微信粘贴、撤销重做；
- 图片拖入、粘贴、上传失败和删除；
- 表格、公式、引用、参数卡和网盘资源；
- 自动保存、断网、重连和多窗口冲突；
- 预览、发布、继续编辑、版本恢复和回收站；
- 键盘操作、焦点可见性和基础无障碍行为。

### 11.3 生产验收

- 主站与现有公开 URL返回预期内容；
- `/cms/` 登录、MFA、三种角色和私有缓存正常；
- 数据数量、媒体引用、搜索、RSS和站点地图一致；
- 稳定时间窗内无 5xx、Traceback 或持续上传失败；
- `hvac.sdzjoy.com`、CloudDrive2、Tailscale 和 ZeroTier 独立可用；
- 新备份可读取，旧镜像与数据库恢复方案可执行。

## 十二、完成定义

- 站长不再看到或操作 Wagtail；
- 最终运行镜像、设置和路由不依赖 Wagtail；
- 新后台最多两次点击开始写作，正文所见即所得；
- 自动保存、预览、发布、版本恢复、图片和专业内容节点可用；
- 主站视觉、栏目和公开 URL保持兼容；
- 账号、MFA、会员、标准库、资源站、搜索和通知继续工作；
- 生产切换有经过恢复演练的备份和可执行回退点；
- 全量自动测试与桌面、手机、生产验收全部通过。
