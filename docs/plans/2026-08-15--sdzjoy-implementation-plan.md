# 少惰主（SDZJOY）技术工作台实施计划

- 设计依据：`docs/plans/2026-08-15--sdzjoy-technology-workbench-design.md`
- 实施分支：`feat/platform-foundation`
- 目标运行环境：香港 Ubuntu 24.04 / 2 vCPU / 约 2 GiB RAM / Docker Compose
- 首选技术：Python 3.12、Django 5.2 LTS、Wagtail 7.4 LTS、PostgreSQL
- 发布原则：现有 `hvac.sdzjoy.com` 持续运行；新站群在受保护预览环境完成全部验收后统一开放

## 实施约束

1. 不停止、覆盖或删除 Tailscale、ZeroTier、CloudDrive2、现有 HVAC 或其他无关服务。
2. 不把服务器密码、Cloudflare Tunnel 令牌、邮件密钥或网盘凭据写入仓库、日志或镜像。
3. 所有数据库结构变化必须有迁移、迁移前备份和回滚说明。
4. 资源文件仍存放在外部网盘；服务器只保存元数据和受控入口。
5. 规范更新默认每月低频检查，遇到限流或来源限制立即停止，不绕过保护。
6. 受限内容的权限必须在服务端执行；公开缓存、搜索和接口不得泄露受限字段。
7. 每一批任务都必须通过测试和格式检查后提交，预览部署前必须完成安全检查。

## 已核验基础状态

- GitHub 仓库初始仅包含已批准设计文档。
- 香港服务器运行 Ubuntu 24.04，2 核，约 2 GiB 内存，根分区约 29 GiB 可用。
- Docker 和 Docker Compose 可用。
- 现有 HVAC Web、HVAC Cloudflare Tunnel、CloudDrive2 为相互独立的 Docker 容器。
- Tailscale 和 ZeroTier 服务正常。
- 现有 HVAC 正式地址返回 HTTP 200。
- 本轮只读核验未修改服务器配置和容器。

## 批次 1：基础工程

### 任务 1：保护基线并建立隔离分支

1. 确认 `main` 与远程一致且工作区干净。
2. 建立 `feat/platform-foundation` 分支。
3. 只读核验香港服务器资源、容器、监听端口和现有 HVAC 健康状态。
4. 将核验结果和保护边界写入本计划，不记录敏感信息。

验证：

- `git status --short --branch` 显示功能分支且没有意外修改；
- `https://hvac.sdzjoy.com/` 返回 200；
- 服务器现有容器仍为运行状态。

### 任务 2：建立 Django/Wagtail 项目骨架

1. 创建 Python 项目配置、依赖清单和环境变量示例。
2. 使用 Django 5.2 LTS 与 Wagtail 7.4 LTS。
3. 建立分层设置：`base`、`development`、`test`、`production`。
4. 建立 `config`、`core`、`accounts`、`content`、`standards`、`resources`、`notifications` 应用骨架。
5. 建立健康检查、站点域名路由和基础错误页。
6. SQLite 仅用于本地快速测试；预览和生产强制 PostgreSQL。

验证：

- `python manage.py check` 通过；
- `python manage.py migrate` 通过；
- 开发服务器健康检查返回 200；
- 测试设置不会连接生产数据库。

### 任务 3：建立质量门禁和本地容器环境

1. 配置 Ruff、pytest、coverage 和 Django 系统检查。
2. 增加 `.editorconfig`、`.gitignore`、`.dockerignore` 和安全的 `.env.example`。
3. 创建非 root 运行的应用镜像、PostgreSQL 开发 Compose 和健康检查。
4. 增加本地启动、测试和数据库迁移说明。
5. 建立 GitHub Actions：依赖安装、静态检查、迁移检查和测试。

验证：

- Ruff 通过；
- pytest 通过；
- `makemigrations --check --dry-run` 无未提交迁移；
- Docker Compose 配置校验通过；
- 镜像中不包含 `.env`、Git 元数据或测试缓存。

## 批次 2：账号、内容和品牌前台

### 任务 4：实现账号与会员基础

1. 项目起始即使用自定义用户模型，以邮箱为唯一登录标识。
2. 建立 L1、L2、L3 等级、状态和变更审计模型；L0 由匿名用户表示。
3. 实现开放注册、邮箱验证、密码重置、登录失败限流接口和会话管理。
4. 为通行密钥和动态验证码预留并实现兼容的 MFA 流程；管理员强制 MFA。
5. 建立 `id.sdzjoy.com` 入口和短时授权码流程；不使用全域长期 Cookie。
6. 实现账号停用、数据导出和删除请求基础流程。

验证：

- 未验证邮箱不能获得 L1 权限；
- L1 不能自行提升为 L2；
- L2 升降级产生审计记录；
- 管理员未完成强验证时不能执行敏感操作；
- 授权码单次、短时且绑定回调地址。

### 任务 5：实现内容模型与后台

1. 创建项目、文章、随记、工具和主题模型。
2. 使用 Wagtail 页面、Snippet、草稿、版本和发布工作流。
3. 实现随记到文章的关系、项目时间线和跨内容关联。
4. 定制中文后台菜单、列表、筛选、预览和操作说明。
5. 实现安全的富文本、代码块、图片、表格和 Markdown 输入边界。

验证：

- 草稿不出现在公开页面、站点地图和搜索中；
- 已发布版本可回退；
- 删除被引用内容时给出保护或明确处理；
- 富文本不能注入脚本；
- 项目页按时间正确汇总关联内容。

### 任务 6：实现现代工程实验室前台

1. 建立设计令牌、明暗主题、字体、网格、卡片和状态标签。
2. 实现首页、项目列表/详情、文章列表/详情、随记、工具和关于页。
3. 建立统一顶部导航、页脚、账号状态和子站切换。
4. 实现响应式布局、键盘操作、可读焦点和基础无障碍。
5. 增加 SEO 元数据、结构化数据、RSS、站点地图和规范化链接。

验证：

- 手机、平板和桌面关键宽度截图通过人工审核；
- 深色和浅色对比度符合基础可访问性要求；
- 页面无明显布局偏移；
- 草稿和受限页面不进入站点地图；
- `www` 跳转策略在预览配置中可验证。

## 批次 3：规范库与资源站

### 任务 7：实现规范、手册和书目模型

1. 实现标准基础信息、生命周期、ICS/CCS、发布机构和编制信息。
2. 实现设计阶段、专业主题、使用性质和数据中心系统标签。
3. 实现标准前后代替、相关标准、相关文章、工具和资源关系。
4. 为手册和参考书建立独立模型。
5. 建立来源证据、最后核验时间、核验人员和状态历史。
6. 实现列表、详情、筛选、关系时间线和数据中心覆盖矩阵。

验证：

- 替代关系不能自指或形成明显循环；
- 状态与关键日期组合经过模型校验；
- 国外参考和国内依据在页面上明确区分；
- 缺少来源证据的记录不能标记为“已核验”；
- 覆盖矩阵可以识别空白类别。

### 任务 8：实现克制的规范变更助手

1. 建立来源、检查批次、候选变更、证据快照和审核模型。
2. 先实现手动创建候选变更和人工审核闭环。
3. 再为明确允许访问的官方公告实现月度增量检查。
4. 实现缓存、单任务、低并发、条件请求、退避和幂等。
5. 任何候选变化都不得自动覆盖已发布数据。

验证：

- 重复运行不会生成重复候选；
- 限流和来源异常停止当前批次并记录原因；
- 拒绝候选不会改变正式记录；
- 审核通过产生状态历史和订阅事件；
- 测试使用本地固定样本，不在 CI 中访问第三方站点。

### 任务 9：实现资源站与分级入口

1. 实现资源、版本、外部网盘入口、权限、版权和失效反馈模型。
2. 实现 Excel/CSV 预览导入、校验、草稿和确认发布。
3. 实现 L0/L1/L2/L3 服务端过滤和入口显示。
4. 实现单个网盘入口隐藏、更换、最后验证和其他镜像继续使用。
5. 不接入网盘账号，不保存网盘密码、Cookie 或长期令牌。

验证：

- L0/L1 不能从页面、API、搜索、缓存或错误中获取 L2 入口和提取码；
- 导入错误不会产生半成品公开记录；
- 单镜像失效不影响其他镜像；
- 权限降级后旧会话立即失去相应入口；
- 日志不记录完整受限链接或提取码。

## 批次 4：搜索、通知与运行保障

### 任务 10：统一搜索、收藏与通知

1. 建立跨项目、文章、随记、规范和资源的统一搜索。
2. 建立收藏、主题订阅、单项订阅和站内通知。
3. 实现重要规范/资源事件即时邮件、普通内容每周摘要。
4. 实现退订偏好、发送幂等、有限重试和失败列表。
5. 权限变化后重建或过滤相关搜索记录。

验证：

- 搜索结果按类型分组且遵守权限；
- 同一事件不会重复发送；
- 退订立即生效；
- 邮件失败不会阻塞内容发布；
- 测试邮件不发送到真实用户。

### 任务 11：生产容器、备份和监控

1. 建立应用、PostgreSQL、任务进程和反向代理的生产 Compose。
2. 为 2 GiB 主机设置明确内存限制、连接数和日志轮转。
3. 实现数据库和媒体每日备份、加密异机复制、清单和校验。
4. 建立隔离恢复脚本和恢复演练记录。
5. 建立健康检查、关键路径监控和分类告警。
6. 为每次部署保留上一镜像、迁移前快照和回滚脚本。

验证：

- 所有容器以最小权限运行，数据库不发布公网端口；
- 备份可在隔离数据库中恢复并通过数据抽查；
- 回滚演练不影响现有 HVAC；
- 日志轮转和容器限制生效；
- 模拟依赖故障时前台按设计降级。

## 批次 5：内容、预览与正式验收

### 任务 12：准备首发内容和数据

1. 选择 5 至 8 个已有项目，形成脱敏草稿。
2. 每篇草稿由用户逐篇确认后才能标记为首发。
3. 建立数据中心暖通规范覆盖矩阵和核心条目清单。
4. 逐条核验官方来源、状态和替代关系。
5. 准备精选资源清单并验证说明、版权、权限和网盘入口。

验证：

- 自动敏感信息扫描无命中，人工复核通过；
- 未确认文章保持草稿；
- 覆盖矩阵无未解释空白；
- 标准核心条目有来源和核验记录；
- 精选资源的全部首发入口有效。

### 任务 13：部署受保护预览环境

1. 对现有服务器配置和相关目录做可恢复备份。
2. 在独立目录、独立网络和独立内部端口部署新站群。
3. 使用新的预览 Tunnel 或受保护路由，不修改现有 HVAC Tunnel。
4. 设置 Cloudflare 访问保护，只有用户和实施人员可访问。
5. 执行数据库迁移、静态资源构建和健康检查。

验证：

- 现有 HVAC 前后均返回 200，数据回归测试一致；
- 现有 CloudDrive2、Tailscale 和 ZeroTier 未中断；
- 预览环境不经授权不可访问；
- 应用重启和服务器重启后自动恢复；
- 服务器资源留有安全余量。

### 任务 14：整体验收与统一开放

1. 执行功能、权限、数据、安全、性能、邮件、备份恢复和回滚测试。
2. 用户完成首发内容、视觉和移动端最终确认。
3. 创建上线前数据库快照和完整回滚包。
4. 配置正式域名路由并验证 HTTPS、缓存和安全响应头。
5. `www` 永久跳转主域名，现有 HVAC 仅接入统一导航和品牌。
6. 上线后连续观察关键路径、错误率、邮件和资源占用。

验证：

- 设计文档第 15 节的全部验收项通过；
- 本计划各任务有测试或验收证据；
- 正式域名外部访问与权限矩阵正确；
- 回滚包在上线窗口内可执行；
- GitHub 代码、部署版本和线上版本一致。

## 批次检查点

每完成一个批次：

1. 运行该批次全部验证；
2. 提交独立 Git commit；
3. 推送功能分支；
4. 汇报完成项、测试结果、风险和下一批动作；
5. 经用户反馈后继续下一批。
